# Contrastive Language Models (CLM)

Open-source state-action scoring models with a TypeSafe-compatible API for typed decisions and candidate ranking.

Reference: <https://github.com/Contrastive-LM/CLM>

Note dated: 2026-09-30 18:00:00+00:00.

CLM is an open-source alternative to [Jev](jev.md) for System One
decisions. It learns to align a state with appropriate candidate actions using
a contrastive objective (InfoNCE). State and action representations are computed
separately, allowing repeated candidates and states to reuse cached embeddings.
It scores supplied candidates; it does not generate an arbitrary new action.

## Released implementation

The reference CLM-v0.1-8B uses a frozen Qwen3-8B backbone with trainable state
and action projection heads. The repository provides inference, a web
playground, fine-tuning, evaluation code, and links to released heads and data.
Its README identifies both repository code and CLM-8B weights as Apache 2.0.
Self-hosting still needs the matching encoder, pooling configuration, model
weights, and sufficient inference hardware; downloading the small head alone
does not provide the 8B encoder.

The HTTP service exposes TypeSafe-compatible `Choice`, `Score`, and `Noul`
questions through `POST /v1/systemone`, plus candidate ranking through
`POST /v1/rank`. This makes it a candidate backend for the same bounded
[workflows](../harness/workflows.md), subject to checking response semantics,
limits, and calibration rather than assuming identical behavior.

The documented serving path runs Qwen3-8B with vLLM's pooling runner and
`clm-serve` as the decision API. The default encoder context is 2,048 tokens;
longer states require raising both serving limits. Context truncation and
candidate coverage matter when applying it to long agent trajectories.

## Evidence and limits

The authors report performance comparable to Jev on their computer-use, gaming,
and tool-calling tasks, with up to 9× lower latency. Treat those as reported
results under their workloads, hardware, and cache conditions, not a universal
latency or quality guarantee.

Their fine-tuned verifier results use **38 held-out DeepSWE tasks** and
**30 held-out Terminal-Bench 2.1 tasks**, selecting among solutions generated by
other models. The reported 81.6% and 87.6% describe that candidate-generation
and selection setup, not CLM independently solving the full benchmarks.
Evaluate held-out task performance, cold and warm cache latency, and calibration
on the intended candidate sets before replacing a production decision model.
