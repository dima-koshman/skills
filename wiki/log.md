- **Creation**: Added [Well-Known Ports (22, 80, 443)](/software-engineering/infrastructure/network-ports.md) after Dima asked whether these ports are special beyond convention and whether SSH and HTTP(S) can swap ports in his Runpod setup. TCP doesn't care. What depends on the number: privileged ports below 1024, client defaults, the WHATWG bad-port list (22 is on it, so no HTTP on 22 in browsers), firewalls, and Let's Encrypt's fixed ports. RFC 9114 lets HTTP/3 use any UDP port. Runpod maps an internal TCP port to an assigned external port, so moving sshd inside the Pod doesn't help on a strict network. Draft.

- **Creation**: Added [Unified CPU-GPU Memory](/ai-engineering/compute/unified-memory.md) after Dima asked how Apple's GPU can share memory with the CPU and whether big GPUs could do the same. Shared memory removes copies but not the device boundary: the GPU keeps its own firmware, queues and scheduler. Compares Apple M3 Ultra, DGX Spark, MI300A and Grace Hopper on capacity and bandwidth. Notes that Apple's current Mac Studio spec page lists 256GB for M3 Ultra, down from 512GB at launch. The Grace Hopper CPU-to-HBM figure comes from a search excerpt.
- **Update**: Added root cause, cost-aware scheduling and co-design sections to [Why GPU Scheduling Differs from CPU Scheduling](/ai-engineering/compute/gpu-sharing/gpu-scheduling.md) after Dima asked whether a scheduler could hide the difference and whether co-designed chips would converge. Cites Chimera and REEF for cost-aware GPU preemption, PTask, the HSA 1.2 spec and MI300A for co-design, and Linux AMX handling as the CPU-side parallel.
- **Creation**: Added [Why GPU Scheduling Differs from CPU Scheduling](/ai-engineering/compute/gpu-sharing/gpu-scheduling.md) after Dima asked whether the difference comes from data loading time. It does not: memory stays resident across time slices. The cost is tens of MB of on-chip registers and shared memory on an H100, so GPUs switch warps for free but programs rarely, and preempted only at thread block boundaries before Pascal. Sources are the CUDA guide, Hopper tuning guide, Pascal whitepaper and Linux XSTATE docs.
